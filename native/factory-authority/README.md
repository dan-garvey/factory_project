# Native authority boundary preparation

This package prepares pure request-history and reach operations for the future
sole native World. It is not connected to the live opening and owns no material
state, Session, Store, native body, simulation clock or fallback. The current
Model remains the live authority. Recovery owns the separate canonical Cargo and
WorkLot evolution; this package neither copies nor edits that material schema.

The composition uses the canonical Bazel graph from `factory-yau.3.17.8.2`.
Its incomplete historical bootstrap remains incomplete; the corrected forward
validation is separate evidence.
The accepted portable values, converter and cog source dependencies are copied
without changes. Source composition is permitted before graph publication; it
does not establish a build, extension load or gameplay result.

## Commands and historical results

Call `inspect_request` before evaluating current actor reach or command rules.
An exact retry returns its original saved record. A changed intent with the same
actor/request pair is refused. Integer, floating-point, boolean and container
differences remain significant. No observation-only comparison is used here.
The World context separates histories; Session still owns peer binding and fresh
request namespaces. This package does not accept a client pose or bypass that
transport boundary.

`prepare_record` returns an uncommitted history candidate and immutable record.
A new accepted command advances order and revision; a new refused command
advances order only. Exact retries create no candidate and never rewrite the
stored revision, body cut, entity or refusal. Additional receipt facts cannot
replace envelope fields. The delivery layer may mark its copied reply as a
duplicate; the stored original must retain `duplicate = false`.

The future World must prepare its rule/material/topology change, validate that
complete candidate and this history, and commit them together on its owning
thread. Do not mutate a live material state and append history afterward. These
pure functions do not implement that transaction or provide an activation API.

## Checkpoint subrecord

`encode_history` and `decode_history` handle a versioned native-value history
subrecord. Counts and schema values require actual integers, flags actual
booleans, and identities exact strings. Records have contiguous original order,
unique actor/request pairs and bounded monotonic revisions. Original intent and
result fields, including admission facts, remain owned copies.

This is not the complete opening checkpoint format and does not change its
schema. The World still must validate command-specific history, entity and work
generations, topology, custody, capabilities and complete state before activation
or native body registration. The Store remains the sole file owner. A failed
full import must preserve the original file and World rather than reset them.

This first adapter permits at most 4,096 records, 100,000 native-value nodes,
depth 32, 1 MiB per string and 4 MiB total string/key bytes per encoded history.
Identity strings are limited to 128 bytes without embedded nulls. These are
explicit adapter bounds, not permanent world or campaign requirements. The
encoded wrapper participates in the same depth and byte budget as decode.

## Reach boundary

`check_reach` consumes a Session-bound actor and a trusted ready producer cut.
The World must derive every target from its canonical topology and capabilities;
neither targets nor body samples are accepted from a client command. All supplied
targets must pass scalar three-dimensional squared distance with no epsilon.
The receipt preserves original target order and cut values. Nonfinite samples or
arithmetic cannot publish a partial or infinite receipt.

This helper does not establish native registration, process lifetime, collision,
readiness publication, placement clearance or capability schema validity. Those
remain mandatory adapter/World contracts. Observation ordinals do not promise
distinct physics frames, and camera position remains irrelevant to permission.

## Validation status

The C++ test source contains invented retry, strict-type, refused-command,
checkpoint-corruption, overflow, boundary and vertical-distance controls.
Existing source checks do not compile this package. Native World tests and the
canonical package build exercise this dependency without proving an engine ABI,
body-registration or gameplay result.

The explicit targets are `//native/factory-authority:authority_boundary` and
`//native/factory-authority:authority_boundary_test`. They are not permission to
queue a campaign. Use the relevant tests and one independent reviewer, retaining
actual source/toolchain/resource records without a separate approval chain.
The native World and Cargo transactions are implemented as logical components;
normal Store/physical restoration and gameplay adoption remain unfinished.
